# T008：检索覆盖与有效经验对照（backlog）

已创建[Issue #15](https://github.com/wang1299/dsh-evolve/issues/15)。依赖T006c，来源为首轮三组无经验暴露的明确缺口；当前为backlog，未宣称已解决。

## 问题和目标

来源经验已验证，但完整任务描述中的许多操作／约束词稀释现有query词项覆盖得分；已知相似的异常回滚任务被两个策略拒绝。提高检索对正常任务描述的适应性，同时保持不相关经验可拒绝、代码／依赖约束不放松。

## 范围与非目标

先建立本地、无模型调用的查询／经验正负样本及语义标签，分开积累／开发与未见评估任务族；比较当前覆盖率、可解释的词项加权或独立摘要策略，说明输入、反馈、数据需求和限制，再做最小改动。不要仅为已经观察的库存任务调查询或阈值；本轮样本作为开发／回归案例，不再冒充未见评估。

非目标：复杂RL训练、放宽来源验证／作用域、由测试通过推断经验收益、自动追加真实模型预算。

## 验收与验证

- 长描述、无关词、短描述、负例及版本不适用案例可复现，开发集与未见任务族无泄漏。
- 同时报告有效经验召回、错误注入、拒绝率和额外成本；允许无改善或回退。
- Evolve核心来源／作用域过滤保持；普通检索对照的方法和预算明确固定。
- 先确定新方案和冻结任务，再安排独立评审与下一批模型运行；不覆盖T006c的原始3次结果。
- 对实际风险补单元／集成测试并跑相关检查；有经验暴露的三组仍需新的独立运行证明。

执行方式沿用任务分支、实现前设计、必要测试、稳定提交独立只读评审及条件合并；用户已恢复自己的GitHub仓库开发，模型预算仍需先冻结，不自动追加旧实验调用。
