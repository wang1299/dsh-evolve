# T016：有限结构诊断验收

Issue [#41](https://github.com/wang1299/dsh-evolve/issues/41)，设计先于实现见[ADR019](../decisions/019-usage-shape-diagnostics.md)。本轮零服务商模型调用/凭据访问，只有内存适配器与本机合成HTTP。

## 实现与使用边界

`diagnoseMessagesUsage`在既有数值判定上返回首处unsupported_usage的固定位置、拒绝类别、usage JSON类型、未知字段数量、最多8个域分隔SHA256字段名指纹及省略数。原`analyzeMessagesUsage`返回形状保持；未知字段及所有计数/终结错误仍拒绝。指纹可与已知字段名重算比较，低熵名称可猜出，不是匿名化；字段名原文、值和任意消息正文不保存。

只有新的固定实验显式构造`new DeepseekBudget(newBudgetPath, policyId, 2)`才写数值回执schema2；默认仍schema1。v2的diagnostic在unsupported_usage时非空，其余为null；统一读取器严格接受v1/v2。回执版本与预算账本schema、policyId和SQLite格式各自独立。旧读取器不支持新v2，无自动迁移或降级；插件公开接口/数据格式/依赖不变。

v2只能给本实例新预留且已持久化的UUID写回执；不能给重启前或历史unknown补造来源。网络前预留/待处理回执、终结回执先持久再settle、写失败停止、完整流及最大预留规则保持。HTTP/传输错误覆盖总体原因时清空局部结构诊断，避免把截断数据当完整流原因。

T011/T015入口保持原样，默认不会启用新诊断；旧冻结脚本摘要/资格也不允许当作新实验重用。不能仅升级源码就声称已重新验证DSH学习或修复真实计费协议。

- 五位置覆盖start顶层usage、start.message.usage未知字段、delta未知字段、stop任意usage、其他事件usage；null/空对象/数组和固定优先顺序可解释。12个未知字段按指纹排序保留8、省略4，插入顺序/值内容不改变身份；严格schema拒绝额外正文/数量不一致。
