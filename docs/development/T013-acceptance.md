# T013：数值用量回执验收

Issue [#34](https://github.com/wang1299/dsh-evolve/issues/34)，[ADR016](../decisions/016-numeric-usage-receipts.md)。依赖已合并PR #35/T012。本轮没有真实模型/新采样。

## 原因与实际能力

T011的两个unknown仍然无法定位根因：原始HTTP SSE不存在，SDK用量估算也不能替代原账本结算。此次给实验代理增加有限数值回执，供今后获授权的实验定位哪一步不满足条件；没有修复原真实实验或释放其费用预留。

每个真正预留的请求在`<budgetPath>.receipts/<reservation UUID>.json`有schemaVersion=1 sidecar。字段为固定model/policy、callId、HTTP状态、观察到的响应字节数、固定reason、最多64条start/delta/stop/error计数快照、其他事件数及可确认usage。原始模型输出、工具正文、Key、任意错误文本/停止原因不保存；非法数字记null，明确的未知停止原因只记unknown。超限时可记录首个超限chunk后的数值字节数，不保留该chunk正文。目录属于本机ignored实验数据，由owner决定清理，不自动删除旧记录。

`complete`只表示数值判定合格；原账本才决定是否已结算。先持久预留/待处理回执后fetch，完整结束后先写回执再settle。两文件不具备跨文件事务；中断可能留下合格回执与未知账本，但重启不据回执退还预算。磁盘失败使实例拒绝新请求，HTTP/截断/异常继续保留全额预留。旧ledger只读打开不补造回执、不改写。

原ADR014保守策略维持：输入/缓存每项不可倒退，所有缓存按未命中高峰价。官方固定SDK允许快照覆盖，因此合成的输入下降/缓存增加变体被本策略拒绝为counter_decreased；这不是T011已观察事实，也没有据此降低预算约束。当前新增不完整SSE帧、未知usage字段/非法数字等明确拒绝原因，不能把诊断失败静默当零费用。
