# 产品需求 v0.1

## 目标与边界

产品是我们自己的 Agent 自进化 DSH 原生插件，暂名 DSH-Evolve。开发组织参考 Run2Skill，产品不沿用其需求或代码。核心体验：“这个问题我上次纠正过，这次 Agent 能自己注意到。”

闭环：失败 → 修正 → 验证 → 提炼并保存经验 → 新任务选择和应用 → 收集反馈 → 更新经验。

第一版限单仓库 Python＋pytest Bug 修复。模型权重保持不变；经验价值更新和上下文选择是优化对象。先做完整案例，不宣称普遍变强。

## 五个模块

1. 采集：任务及明确纠正、相关工具调用和结果、失败与最终修改、必要 diff、命令与结果、环境、仓库 commit 和依赖指纹。明示任务开始／结束及 session 归属；空闲仅触发调度。
2. 提取：适用条件、事实证据、推断、建议、修复策略、验证方法、来源任务、版本约束、状态、修订及使用历史。不能将一次成功泛化成通用规则。
3. 验证：从 Git 快照建立两个独立临时目录，以固定的外部验收文件分别运行失败版本与修复版本，另跑回归。缺少证据、原始失败无法复现或回归失败都保留候选。验证不能修改原仓库。
4. 选择：先过滤仓库、代码和依赖条件，再按相似度与已观察效用排序；每任务最多一条经验，可不注入。记录选择理由、实际使用、反馈及成本。
5. 生命周期：追加证据和修订、负反馈停用、代码依赖变化重新检查、历史与原因可查、人工纠正和恢复版本。恢复经验策略不回滚用户代码。

## MVP 验收

- A1：失败测试和修复来自同一显式任务和仓库，task/session/run id 可追溯。
- A2：隔离运行同一独立测试，失败版本失败、修复版本通过、修复版本回归通过；环境和内容摘要可核对。
- A3：保存候选及来源证据；事实、模型推断、建议分开；未验证条目不可按已验证经验自动应用。
- A4：另一个相似任务可获取符合代码／依赖条件的经验；仓库、依赖、代码条件不匹配时不注入。
- A5：反馈关联实际应用记录；拒绝、反例和撤回可停用；修订和恢复保留不可变历史及原因。
- A6：本地最小面板展示经验、来源、验证状态、使用历史，能执行受保护的修订／停用／恢复操作。
- A7：固定 DSH 发行版，使用真实官方服务做兼容探针；记录未覆盖的真实模型会话和安装范围。
- A8：三组评价协议和数据格式可复现，未进行真实 Agent 实验时结果必须标记未运行。

## 采集与清理

默认只在本地显式数据目录保存必要字段；不存完整聊天和任意工具输出。文本先限制长度并脱敏；未可信内容不作为可执行指令。文件路径相对仓库，拒绝越界和符号链接逃逸。保留期限默认30天，清理只删除本插件已过期证据；经验历史及用户代码不随清理删除。首次授权仓库和验证命令后才允许运行项目代码。

自动模型提取是可选能力：未配置时允许用户／工具提交结构化候选，不能伪称发生了 LLM 提取。向外部模型传送真实材料须获得用户对采集与传输范围的授权。
