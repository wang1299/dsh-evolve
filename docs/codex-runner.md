# Codex CLI 本地模型执行

这是经验核心的可选实验执行器，产品的DSH适配层仍保留。设计与边界见[ADR-007](decisions/007-codex-executor.md)。它不联系Mini Claude Code仓库。

## 使用

需要本机安装Codex CLI并自行完成`codex login`。程序调用CLI，复用其认证；不读取、复制或持久化登录凭据。本轮兼容目标为本机`codex-cli 0.163.0-alpha.10.2`。

```sh
npm ci --ignore-scripts
npm run check
npm run codex-demo -- --live
```

`--live`明确启用模型调用，会使用当前Codex账号额度；没有此参数时脚本不调用模型。可用`EVOLVE_CODEX_BINARY`指定本机实际可执行文件，用`EVOLVE_PYTHON`指定已有pytest的Python。CI只运行确定性的本地子进程协议测试，不登录、不调用模型。

每轮最多三次模型请求，每次90秒。限制工具次数、输出字节和提示字节；token usage事后记录，金额未知。不承诺CLI接口没有提供的token/金额硬上限。

超时/取消会请求终止子进程树；父进程已退出、后代仍持有输出管道时，最多额外等待250ms后关闭宿主管道并失败返回。已经脱离进程组的后代可能继续存活，不能将其称为可靠的全后代隔离。

默认使用调用级`evolve-https` provider关闭WebSocket，仍由CLI管理现有认证及默认端点，不修改用户config。本机默认WebSocket超时，独立HTTPS最小请求已成功；完整案例结果另行记录。接入根据固定版本的官方provider配置与实际兼容检查，不覆盖保留的内置provider。

## 执行顺序

1. 在新临时目录生成只含合成Python代码的Git仓库，以及仓库外部的两套pytest验收。
2. Codex在只读sandbox中返回结构化源码修复与候选经验；提示只包含任务、允许的源码及可选经验，未包含验收答案。
3. 宿主验证允许路径、原文件摘要和大小，写入指定源码并提交；调用已有服务保存候选并验证来源失败/修复/回归。
4. 从同一目标提交创建两个实验分支，分别无经验、提供当前机制选择的经验，运行同一相似任务和外部验收。
5. 输出`.probe-work/codex-demo-*/evidence.json`，保留失败、usage、实际经验版本与测试结果。只有实际执行完才能声称该阶段通过。

模型没有直接写权限；修复写入由宿主允许列表控制。只读执行器不能证明模型从未读取验收路径，当前合成演示不是防泄漏的正式任务集。经验通过测试后才可选择，模型自报完成、CLI退出0和turn完成均不能代替独立验收。

## 保存与清理

不保存完整对话、推理、原始JSONL、任意工具输出或stderr；错误只保留固定原因和分类，不保存自由文本服务端诊断。结构化修复仅含合成源码。CLI使用ephemeral，不保存该次会话rollout；认证仍由原有CLI管理。

生成的仓库、外部验收及SQLite位于本轮临时目录/ignored `.probe-work/`中。实验报告保留它们的必要引用；清理请明确指定本轮生成的目录，避免清理用户原有数据。

## 结果解释

两个新鲜会话共享相同目标代码；修好的来源函数也对两组可见。单个合成任务对只能检查接入和经验提供，不能证明普遍收益或因果效果。CLI默认底层模型身份、温度未冻结，金额未知；当前记录不伪装成已有三组评价格式。

完整三组对照、真实任务集与重复样本、DSH真实模型会话及完整发行应用安装仍待T006完成。

## 明确指定的失败阶段续跑

仅当合成案例已完成来源验证和baseline、evolve失败且仓库仍在原干净起点时，可以显式增加一次模型调用：

```sh
npm run codex-retry -- --live --evidence <原失败evidence.json> --repo <本轮生成的repository目录>
```

脚本核对仓库身份、起始提交、原经验版本、提示摘要和完整验收文件集合，随后按原证据摘要原子登记单次资格；同parent重复/并发拒绝，失败不自动释放资格。复用原应用记录，另存`codex-retry-*`报告；不改写原失败证据或恢复旧CLI会话。新增一次evolve调用后两组预算不同，结果只能验证接入和验收，不能用于等预算收益比较。历史实际结果及资格修复前两次续跑的登记见[T006b验收](development/T006b-acceptance.md)。
