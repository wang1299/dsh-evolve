# ADR036：保留首发标签的显式发行恢复

2026-10-23，T033 / Issue #75；基线 `4bd55a5`。在恢复流程实现前记录。用户已再次明确授权发布 npm 包和 GitHub Release。

## 已发生的事实

`dsh-reforge@0.1.0-alpha.1` 已由 `wang129` 发布至 npm `alpha`，公开下载摘要与冻结包一致，固定 DSH 0.2.0-rc.2 的全新公开安装通过。注释标签 `v0.1.0-alpha.1` 的远端对象为 `5035a5b59e85ca7becdf19aaac0eab18333e4ddd`，指向已验收源码 `4bd55a594ac75bdf4cfb331d94944026bbcc1578`。

首个发行工作流 [39911777719](https://github.com/wang1299/dsh-reforge/actions/runs/39911777719) 在创建 Release 前失败。日志证明 checkout 先取得真实注释标签，随后把提交 SHA 强制取到同名本地标签引用，导致 `cat-file -t` 变为 `commit`。现有发行脚本据此拒绝继续；远端标签和 npm 制品没有改变，尚未创建草稿或 Release。

## 决定

保留 ADR035 的源码、npm、完整性、发布者和草稿附件校验。不得移动远端标签、改动已公开包、重发版本或把轻量标签视为注释标签。

修复工作流明确检出唯一首发标签，并在发行前从 origin 精确重新获取该标签引用。只替换当前 runner 的引用；之后仍由原发行脚本核对对象类型、注释内容、HEAD、main 祖先关系和公开 npm 字节。新增本地合成 Git 回归，复现引用被提交替换，再执行工作流的实际恢复命令，证明注释、HEAD 和远端对象保持。

已存在的 tag push 运行使用旧工作流，不能靠重跑使它加载修复。因此新增无输入的 `workflow_dispatch`，只允许从 main 显式触发，固定处理 `v0.1.0-alpha.1`。恢复工作流仍检出原标签源码；传给原脚本的 `GITHUB_REF` 在该进程内固定为这一个标签，不以 main 的源码或产物冒充已发布版本。权限继续仅在发行 job 使用 `contents: write`，不新增账号、仓库设置或长期凭据。

实现经稳定 SHA 独立只读评审、当前头双平台 CI 和仓库规则核对后合并，再触发一次恢复。调用结果未知时先读取运行与 Release 状态；发现任何已有草稿或公开 Release 时停止并检查，不自动覆盖或重复创建。恢复成功后下载全部三个公开附件并核对原 npm 制品、SHA256SUMS 和 release.json；最终远端结果追加 Issue #75。

本修复不改变产品接口、SQLite v9、经验身份、预算、授权、提炼次数或跨路径复用能力，不调用模型。npm 阶段曾经过后台处理，CLI 上传成功与公开可下载仍分别记录。
