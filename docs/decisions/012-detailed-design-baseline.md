# ADR-012：细化需求与架构基线，区分目标契约与现行实现

日期：2026-10-19。T009，Issue #27。本次是文档设计，实施代码基线为`bd724ccf03eb50314b29e132df1cbf6210c6c81c`；不改变数据格式、工具/HTTP接口、权限、依赖或模型调用预算。

## 背景与授权

用户明确要求将DSH-Evolve的产品需求与架构总纲细度对齐Run2Skill。参考范围由原开发组织方式扩展到文档颗粒度；产品目标仍以本会话确认的五模块及单仓库Python/pytest修复闭环为准。参考快照`qkycir-123/dsh-run2skill@cfd288ebd0839aa82e65b118d10a85b6b1b61f35`，只读研究章节组织、契约深度和需求追踪方法，不复制实现或引入其Skill发布产品。

## 决定

1. 原路径`docs/product.md`、`docs/architecture.md`升级为文档v0.2，保留A1-A8并新增稳定需求ID、主/异常流程、数据状态、边界与验收映射。文档版本不等于npm版本、SQLite版本或评价schema版本。
2. 产品文档规定目标行为；架构分别描述当前代码事实与明确标注的目标设计。自动证据归并、后台提炼/恢复、DSH原生交互和强隔离等不因写入设计就变成已实现或已验证。
3. 保留现行TypeScript/Node核心、SQLite v2、DSH薄适配与独立本地面板；不将参考项目的DSH Storage Domain、完整Skill Catalog、人工Skill发布/CAS等机制移植为本产品要求。
4. 当前五个DSH工具、Config、核心对象和HTTP接口按源码记录；未来证据引用、后台Job/ExtractionPort/上下文DTO仅是目标逻辑契约，不新增现行字段或接口。涉及实现/持久化/公开接口变化时须另有任务级设计、迁移和兼容验证。
5. 对当前实现不足给出缺口ID、现有依据、后续任务依赖和验收。测试项和运行证据分开；CI组件通过、Windows完整Web安装、Codex合成实验及真实DSH学习不得混用。
6. 需求追踪覆盖每个编号要求，允许“部分覆盖/待实现”，不以现有测试名冒充目标已通过；指标保留未知、失败和无改善。

## 验证与边界

核对源码/测试/既有ADR，检查需求ID唯一、交叉引用与文件链接、图表和状态一致，审查Git diff确保只有文档变更。当前头CI和独立只读设计评审通过后合并；不为纯文档增加镜像实现的单元测试、不重跑模型/重型本机试装。原始会话、安装配置、模型报告和令牌均不进入公开文档。
