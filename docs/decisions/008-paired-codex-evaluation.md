# ADR-008：三组初步对照与诚实的执行控制

日期：2026-10-19。状态：采用；实际运行、测试与独立评审单独登记。

## 问题与选择

T006b已用真实模型生成经验并在相似任务中提供，但底层模型未知、两组重试预算不同，不能用于收益判断。增加T006c：固定显式模型名、推理档位、CLI版本、宿主执行策略、经验库和任务快照；每组一次调用，无续跑。

本轮采用本机目录中可用的`gpt-6.1-sol`、`low`，CLI `0.163.0-alpha.10.2`。这是固定请求路由，不声称固定服务端权重revision。官方CLI没有为本接口提供已核实的temperature、sampling seed或整回合token/金额硬限制：记录null和控制限制，不虚构0或seed。重复编号为replicate，不是模型随机种子。

## 执行边界

- 复用T006b本地、只含合成内容的成功来源报告：校验结构与源码摘要，在新合成仓库重放其模型修复和独立来源验证，生成新的任务/证明，manifest记录原报告摘要和ID映射；不伪造跨仓库经验作用域。
- 新评估任务与来源任务不同，三组从同一目标提交、同一源码输入和同一外部验收开始。只有提示中的经验字段按策略不同；不把验收内容放入提示。
- baseline不给经验；retrieval仅按文本相似度；evolve使用当前核心验证、适用条件及历史效用机制。经验库只读冻结，评估中不写反馈或学习新经验，避免组间污染。
- 每组一次CLI调用，90秒、工具上限0、固定提示/输出大小上限。CLI调用级关闭provider重试；观察到任何工具事件的运行失败且不应用其输出。只接受零工具的源码提案，随后宿主按允许列表写入，并在外部pytest验收；不宣称完整自主工具循环。
- 每个任务/replicate/arm在模型前原子保留资格并写running记录；失败、崩溃/未知和已消费资格保留，不自动补做。CLI失败不使后续组失去执行机会。
- 来源和评估数据均为手写合成案例；本轮先一个任务、三组、一轮。结果永远标记preliminary，不以3次调用宣称泛化效果。

### 首轮执行后的补充（2026-10-19）

首轮三组均通过，但两个经验策略均因低相似度拒绝注入，三组实际提示完全相同。原始3次调用保留，不补做或调整查询以追求结果。评价报告必须展示实际提供经验的次数，将此情况标为`no_experience_exposure`，不能解释成有效的经验收益对照。后续同一合成配方在模型调用前要求retrieval和evolve都确实选入来源经验，否则留下计划／准备失败并消耗0次模型调用。产品仍允许不注入；此门槛只用于预期比较经验的实验配方。检索对冗长任务描述的适应性进入后续任务，不在本轮修改核心算法。

## 评价格式 v2

保留已有v1读入，新增独立v2格式：manifest包含冻结控制和经验库/任务定义；runs关联预先确定的runId、taskId、replicate及arm，保存实际调用控制、提示/源码/验收摘要、精确经验引用、运行状态及独立验收结果。温度、sampling seed、token/金额硬上限、服务端模型revision为null，并解释不可控项。

一致性验证必须拒绝：任务/积累泄漏、不一致控制/任务快照/经验库、重复或缺失组、未知运行引用、baseline注入、失败调用冒称验收通过、未完成状态冒称结果、不同底层来源混合。usage和成本缺失为unknown。主要展示每组尝试总数、验收通过数、未完成数、全部失败及对照差异；不只对成功模型调用计算漂亮指标。

CLI `evaluate`按schemaVersion分派，既有v1文件不迁移、不改写SQLite。

## 限制与参考

固定请求模型名不保证服务端不可变；预算是相同的调用/时间/工具/输入输出策略，不是相同实际token或金额。来源样本小、任务手写、调用顺序和服务端采样不可控，结论只能是初步接入结果。真实仓库任务、更多任务族、重复次数、DSH正常模型会话、恶意代码隔离及完整应用安装仍属T006。
