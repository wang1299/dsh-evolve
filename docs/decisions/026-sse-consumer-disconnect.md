# ADR-026：SSE 消费者提前关闭与上游完成边界

状态：接受；T024 / Issue #57。实现前设计，基线 bc38fec。

## 问题

实验预算转发器在下游 HTTP 关闭但尚未由服务端 end 时立即取消上游。合法模型客户端可能在读完 `message_stop` 后释放响应，而此时上游 HTTP 还未 EOF。转发器会自行破坏最后的完成证据，使费用保留为 unknown。

## 决定

- 终端帧前下游关闭，继续立即取消上游，保留预留。
- 只有当前完整缓冲通过现行严格 SSE/usage 判定时，下游关闭才允许上游继续排空；不再向已关闭的下游写数据。
- 允许排空不等于允许结算。必须在原 60 秒截止时间和 1 MiB 响应上限内读到正常上游 EOF，再对全部字节重新判定，先写回执、再结算。
- 终端帧后额外事件、上游错误、超时、用量异常或持久化失败，仍保留最坏未知占额。
- 不改价格、每次预留、HTTP/逻辑次数、回执或账本格式；不回填或释放既有 unknown。修复只影响之后实际执行的调用。

## 验证与限制

离线真实 loopback HTTP 消费者主动取消，延迟上游 EOF，覆盖完整、缺终端、终端后错误及非法追加事件。保留现有磁盘失败、响应上限和预算重启检查。没有新增模型请求；本设计不解决 Windows 沙箱权限，也不构成来源修复或经验收益证据。
