# ADR 010：有来源的反馈检索记忆

日期：2026-10-19。T008b是#15的子任务，范围为反馈驱动的检索边界；不宣称通用意图/同义理解，不追加真实模型调用。

## 需求和选择（实现前）

T008a仍会将修复经验提供给只修改相同问题说明文字的任务，也会漏掉无标题词重合的任务。避免为已见查询编造同义词或关键词规则：利用本地已保存的应用及owner反馈，派生可追溯的检索记忆。

1. 新增反馈`irrelevant`（经验不相关），与`rejected`/`counterexample`区分。前者只记录此任务上下文的错误选择；后两者仍停用当前实际应用版本。`irrelevant`不计策略成功/失败效用，也不撤销来源修复证明。面板明确各自含义，Agent仍无写反馈工具。
2. 只读取当前经验精确revision、同仓库、非来源任务的真实应用；每个已脱敏任务摘要规范化为NFKC、小写和合并空白。按SQLite反馈追加顺序，每个上下文最后一条非unknown反馈生效。未知不算正例。只有accepted上下文可作替代表述；irrelevant为该**完整规范化摘要**的拒绝记录，不推广为语义/否定规则。新accepted可纠正同一上下文的irrelevant，记录均保留。
3. Evolve先做原来源/作用域资格过滤，再排除被owner标不相关的相同上下文。先用未变的BM25原文；仅当所有合格原文均拒绝时，才用最近最多8个accepted任务摘要作备用检索文档。复用原BM25词项/门槛，按经验合并最高分，原反馈效用及最多一条不变。检索原因保存反馈/应用/来源任务ID和方法版本，明确这是根据owner反馈推断相关，不是经验收益证明。
4. 未记录反馈时保持原行为；没有先前已接受应用时，不解决首次同义漏选。错误accepted可能引入坏表述；全摘要相同的拒绝不能解决新措辞的意图误选。不会将上下文加入经验正文或泛化规则，不创建skill，不复制全会话，也不自动回滚代码。

## 格式、接口与兼容

反馈JSON enum增加irrelevant，现有任务/经验/应用/SQLite表结构及数据库版本2不变。新程序读取旧反馈无迁移、无数据改写；包含新enum后旧程序不能解析，需全部使用新版本，不能在同一数据库混跑或直接降级。没有删除记录。恢复/修订新revision不继承旧表述或拒绝；必须重新验证和积累。

核心select新增可选策略参数，默认feedback-v1，明确冻结bm25-v1模式可复现T008a。既有Codex配对选择器固定bm25-v1，且遇irrelevant反馈拒绝该旧配方；现有模型配方和policyDigest不被悄悄改成新策略。评价器仍可读已有报告。后续评估feedback-v1需要新的明确配方/任务/预算，本任务不实现或运行它。

来源证明依旧不能被accepted别名绕过。选择派生只用已有最小任务摘要，正表述上限8/版本，拒绝只派生摘要摘要值；不另存会话。经验库冻结摘要已含反馈及相关应用，需补入这些应用的任务摘要/仓库输入（不是所有会话），否则无法冻结新检索输入；更新摘要算法只影响新生成的bank digest，不改写已有实验。

## 验收与限制

实现前固定[反馈场景](../../test/fixtures/feedback-cases.json)，仅为开发/回归夹具，不称新留出、盲测或收益数据。

- accepted过渡描述可在之后无标题词重合任务中复用；无反馈/unknown/旧revision/不同仓库/来源自用/缺失关联不进入备用库。
- 相同上下文irrelevant阻止重复提供且经验仍来源已验证；另一修复任务仍可使用；rejected/counterexample仍停用；追加accepted可解除同上下文拒绝。
- 资格、代码/依赖条件、每任务最多一条与版本恢复不放松；最多8个备用表述，重复上下文去重，先原文后备用，负反馈/证据链原因可解释。
- 已有37项及真实源pytest集成、面板HTTP、DSH固定组件兼容、已知报告复现；当前头两平台CI/实际包安装与独立只读评审后才合并。旧36条数据和报告不覆盖。

方法借鉴[相关性反馈](https://nlp.stanford.edu/IR-book/html/htmledition/relevance-feedback-and-pseudo-relevance-feedback-1.html)中利用明确正负反馈调整检索；此处不是Rocchio、MemRL或GEPA复现。反馈来源是owner追加记录，数据至少需要一个有明确accepted的相关应用，零反馈退回BM25。新规则无训练；少数夹具只证明状态和边界，不能推断一般召回/误选或Agent收益。文字判断仍可能有偏，成本随已存反馈/任务增长，后续再基于实际数据决定索引/缓存。
