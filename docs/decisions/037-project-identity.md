# ADR037：统一当前项目身份与 GitHub 仓库名称

2026-10-23，T037 / Issue #85，实施前设计。用户明确要求 GitHub 仓库和当前项目统一为 `dsh-reforge`。工作基线 `cf1aa3a333bd4876d87226636f31ecd968fdb500`，包含前一首页排版任务；合并前须衔接其最终 main，不能丢失该结果。

## 决定

用户追加要求清理外部参考项目的名称、链接、致谢和对照资料。当前工作树改为本项目独立说明，移除专门的外部参考记录；自身需求、架构与验收内容保留，原始历史留在 Git 中。

1. 将同一 GitHub 仓库重命名为 `wang1299/dsh-reforge`，保留仓库 ID、Issues/PR/提交/标签/Release。更新 origin、元数据、CI 条件、徽章、素材和文档地址；不创建替代仓库，不重写 Git 历史，不复用旧仓库名。
2. 当前品牌、临时目录、原生页面/通信/提示区/消息来源及包 patch 行统一新名。客户端与服务端同时更新；认证、请求体上限、仓库和 revision 校验不变。内部 `evolve_` 工具、SQLite 文件/表/版本、默认数据位置及通用类型名不属于包/仓库品牌，不为文字一致而搬迁或改写它们。
3. 旧配置变量、旧消息来源、历史用量诊断域及首发制品原仓库身份集中放入显式兼容常量。保持原字节和语义，不通过拆字拼接隐藏旧名，不清空预算/unknown/已用 grant，不让新名称消除历史费用占额。
4. patch 行从旧 ID 迁到新 ID。自定义 profile 若曾按旧 ID 覆盖配置，升级前须停机、备份，并仅改该行 ID，保持 config/dataDir/授权对象不变；不允许旧行和新行双运行。加入合成 profile 升级演练，验证同一库的旧行、经验、应用和授权不变。当前实际用户继续使用冻结首发包，本轮不自动升级私人环境或重放任务。
5. 当前源码仍是未重新发布的开发树。更新源码里的仓库元数据不能伪装为已发布包也变更；首发 tag、npm 制品、Release 附件及其原元数据不可变。历史验收与 ADR 保留当时语义；可以把浏览链接转为新仓库，但不得把旧发行来源捏造成新地址。首发制品验证单独接受被准确摘要绑定的历史元数据，当前源码的 manifest 必须使用新地址。
首发已完成，冻结源码的旧仓库校验不适用于改名后的当前仓库。保留首发恢复流程供历史查阅，但显式停用其发布 job；本轮不恢复或重建已存在的 Release。后续发行须以新版本、明确授权和独立审查的流程进行。

6. 文档中的当前说明统一新名；必要旧名仅在兼容/迁移和历史发行事实中保留并明确用途。目录收录请求更新为新公开地址，同时说明包名不变、旧地址跳转和首发元数据不变。不重新申请，也不将已提交当作已收录。

## 验收

先留失败回归，再实现入口与元数据变更；运行类型/静态/构建、针对和完整测试、固定 DSH 兼容、实际新包安装/零模型合成学习及 profile 保全演练。名称盘点输出例外清单；当前头双平台 CI、稳定 SHA 独立只读审查和仓库规则后合并。远端更名检查同一仓库 ID、新地址可访问、旧地址跳转、Git 操作、Issue/Release 保留及素材可访问。

不新增模型调用，不发布新版或改变 npm 安全配置，不扫描或上传私人配置/会话，不篡改历史证据。更名若失败或结果未知，先回读同一仓库 ID 与两个公开地址，不盲目重复创建或移动仓库。
