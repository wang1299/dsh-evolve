# ADR024：安装包级自动学习离线验收

日期：2026-10-19。T021／Issue #51，基线bd7d7fa。用户授权继续安装和零付费准备；没有新增真实模型预算。本任务不改产品数据格式、六工具、提炼授权或旧实验资格。

## 缺口与选择

T014演练通过手工propose/verify/link形成经验；T020组件测试覆盖自动候选，但现有安装探针只证明Loader/六工具。本次在真实安装tgz后，经官方Loader加载插件，使用真实AgentLoop和固定脚本Adapter，跑自动候选到新会话应用的机械流程。不得以源码bindDsh替换安装组件，不以模型自评、DB应用记录或idle冒充交付/验收。

## 固定流程

1. 全新合成Git仓库、外部验收、学习库/profile；安装包编译JS逐文件核对源码构建摘要。默认安装探针保留原模式，显式--learning开启开发演练。
2. 脚本Agent调用begin/correction并返回有限修复提案；宿主检查限定函数/路径后写入合成文件及commit。明确用户纠正只从实际合成用户输入取得。Agent finish后后台验证和自动提炼，不能调用propose来补候选。
3. 等待ready与唯一自动candidate，验证完整来源、candidate非激活及grant消耗；宿主模拟owner检查候选后，在真实用户消息中提供reviewedCandidateId，再让同一Agent显式调用verify，检查返回结果及完整引用。不用Adapter私有状态替代模型实际收到ID；后台候选主动通知/发现仍是后续体验缺口。
4. 新真实Agent会话begin取得精确经验/版本；确认实际tool/result回执进入该会话且模型后续调用含该回执，再接受有限目标修复提案。目标commit后显式finish。独立目标pytest使用另一仓库外验收；原来源成功不能替代它。
5. 仅在目标独立验收通过后，由宿主通过实际安装包本机面板API追加“合成基准验收反馈”，不伪装成真实owner评价。记录精确application/revision和反馈。负路径包括坏提炼输出、关闭共享与无效目标修复；失败保留partial和原因，无伪造反馈。

来源与目标都在同一仓库，目标代码在来源任务begin之前已存在；目标修改不改变来源scope文件。静态插件acceptance配置仍用于来源，目标验收独立执行并单独报告；不把目标自动证据包不完整强行改成ready。

## 隔离、报告与边界

脚本只注册进程内offline provider、无真实provider/Key配置、无模型HTTP；使用最小运行环境和全新profile，不复制现有会话或凭据。报告只保留任务/经验/引用标识、commit、数值测试与步骤/调用计数、模式/包摘要及明确limitations；不写完整对话、代码提案、原始模型响应、token URL或任意异常正文。报告与测试DB在ignored目录，公开验收文档仅写合成摘要。

组件演练由项目固定官方依赖提供服务单例；实际插件来自tgz。完整WindowsCLI/Web另在新的隔离home/profile安装同一源码编译版本，并检查加载/重启；官方host可复用已固定的独立安装而不改其内容。两者证据分别记录，不能声称已验证完整发行应用上的真实模型学习。真实DeepSeek连接、提炼质量和三组未见任务收益留待新预算与独立实验，旧预算不重置。

按设计/复现缺口、任务分支、检查、Draft PR、稳定SHA独立只读审查、修复和两平台CI合并推进；CI实际包检查增加显式学习模式，普通check不执行网络安装。日常测试环境不自动更新，包/Release不发布。
